# REPLコマンド

*English version: [repl-commands.md](repl-commands.md)*

対話式コンソールの中では、`.`で始まらないものはすべてSQL(SQLite方言
——DDL、DML、TCLの`BEGIN`/`COMMIT`/`ROLLBACK`もすべて使える)として扱われる。
`.`で始まるコマンドはExecDB独自の制御コマンドで、意味の通じるところは
`sqlite3` CLIをお手本にしている。

## データベースを覗く

| コマンド | 内容 |
| :--- | :--- |
| `.tables` | テーブル名の一覧を表示する。 |
| `.schema [TABLE]` | `CREATE`文を表示する(全オブジェクト、または`TABLE`のものだけ)。 |
| `.help` | 全ドットコマンドの一覧を表示する。 |

## 出力の書式

| コマンド | 内容 |
| :--- | :--- |
| `.mode MODE` | 出力形式を設定する: `list`(デフォルト、`\|`区切り、ヘッダなし)、`column`(列幅を揃える、`.headers`を自動でonにする)、`csv`(RFC 4180、CRLF改行)、`json`(行オブジェクトの配列。BLOBは16進文字列)、`line`(1行に`name = value`を1つ)。 |
| `.headers on\|off` | 列名ヘッダの表示/非表示を切り替える。`.mode column`へ切り替えると自動でonになる——不要なら後から個別にoffにする。 |

```
execdb> .mode column
execdb> .headers on
execdb> SELECT * FROM users;
id  name
--  -----
1   Alice
2   Bob
```

## データの保存と読み込み

| コマンド | 内容 |
| :--- | :--- |
| `.snapshot [FILENAME] [--timestamp]` | 現在のインメモリ状態を、新しい単独の実行ファイルとして書き出す。デフォルトは実行中バイナリの名前(または`-o`の値)、`--timestamp`でタイムスタンプを付与する(詳細は[CLIオプション](cli-options_ja.md#タイムスタンプ付きファイル名)参照)。 |
| `.overwrite` | 現在の状態を*この*実行中のファイル自身へ書き込み、その後終了する。「終了時の自動保存は行わない」(仕様書§4)という原則における唯一の例外——意図的な「編集して閉じる」というワークフロー。 |
| `.load FILE` | インメモリのデータベースを、別のExecDBファイルに埋め込まれたデータ(そのファイルのエンジンではない)で置き換える。ファイル自体は生成**しない**——永続化するには続けて`.snapshot`/`.overwrite`を実行する。 |
| `.dump [PATTERN]` | スキーマ+データを、そのまま再実行可能なSQLとして表示する(`LIKE`パターンで対象テーブルを絞り込み可能)。この出力を別の`execdb`プロセスへパイプすれば同じ状態を再現できる。 |
| `.import FILE TABLE` | CSVファイルを一括で読み込む。`TABLE`がまだ無ければ、ヘッダ行から(全列TEXTで)`TABLE`を作成する。既にあれば、1行目からデータとして扱う。`.mode`の設定に関わらず常にCSVとして読む。列数が合わない行があると、そこで全体を中断する(部分的な取り込みはしない)——これは`sqlite3`(警告を出して継続する)とは意図的に異なる挙動。 |

```
execdb> .snapshot bug_123 --timestamp
Wrote bug_123_20260901120000
```

## セッションの終了

| コマンド | 内容 |
| :--- | :--- |
| `.exit [CODE]` / `.quit [CODE]` | 終了する。保存確認のプロンプトは出さず、自動保存もしない——既に`.snapshot`/`.overwrite`を実行していない限りデータは消える。`CODE`を指定すると、そのプロセス終了コードで即座に終了する。 |

プロンプトでのCtrl+D(EOF)は`.exit`と同じ扱いになる。対話端末での
Ctrl+Cは`sqlite3`スタイルの*中断*であり、無条件の終了ではない: 実行中の
クエリがあればそれをキャンセルし、アイドル時なら入力途中の複数行文を
破棄し、間に何も入力せず連続2回押した場合のみ強制終了する(終了コード
1)。パイプ/スクリプト経由の入力(TTYなし)ではこの挙動は一切効かない
——そこでのCtrl+CはOSの既定動作(即座に終了)のままなので、`execdb`を
起動したスクリプト自体はCtrl+Cで期待通り止められる。

## 採用していないコマンド

`sqlite3`由来のコマンドのうち、以下はExecDBが持たないマルチDB・
ファイルベースのモデルを前提とするため、意図的に非対応としている:
`.open`/`.databases`(DB切り替えの概念が無い——常にメモリ上に1つだけ)、
`.backup`/`.restore`(`.snapshot`に役割が置き換わっている)、
`.session`(変更追跡セッション機能)。
