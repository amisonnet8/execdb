# CLIオプション

*English version: [cli-options.md](cli-options.md)*

```
execdb [options]
```

| 短縮形 | 長い形式 | 型 | デフォルト | 内容 |
| :--- | :--- | :--- | :--- | :--- |
| `-p` | `--pg-addr ADDR` | string | 未指定(無効) | PostgreSQL互換ワイヤープロトコルのTCP待受アドレス(例: `:5432`、`127.0.0.1:5432`)。省略すると外部インターフェース自体を起動しない |
| `-s` | `--socket PATH` | string | 未指定(無効) | 同プロトコルをこのUNIX Domain Socketパスでも待ち受ける(例: `/tmp/.s.PGSQL.5432`)。`-p`と`-s`は併用も単独指定も可能 |
| `-u` | `--user NAME` | string | 未指定(Zero-Auth) | 外部インターフェースにこのユーザー名+パスワードを要求する。詳細は下記[認証](#認証)を参照。REPLには影響しない(REPLは常に認証なし) |
| `-o` | `--snapshot-as NAME` | string | 未指定 | `.snapshot`、およびサーバーモードのシャットダウン時自動保存で使うデフォルトファイル名 |
| `-t` | `--timestamp` | bool | `false` | 保存ファイル名に`_YYYYMMDDHHMMSS`形式のタイムスタンプを付与する。詳細は[タイムスタンプ付きファイル名](#タイムスタンプ付きファイル名)を参照 |
| `-i` | `--snapshot-interval DURATION` | duration | `0`(無効) | この間隔で定期的にスナップショットを保存する(例: `5m`、`1h`)。REPLモード・サーバーモードどちらでも有効 |
| `-n` | `--no-repl` | bool | `false` | サーバーモード: REPLを起動せず、外部インターフェースだけをバックグラウンドで動かす。詳細は[サーバーモード](#サーバーモード)を参照 |
| `-q` | `--quiet` | bool | `false` | 起動時バナーを抑制する |
| `-h` | `--help` | bool | — | 使い方を表示して終了する |

外部インターフェースに到達可能にするには`-p`/`-s`の少なくとも一方が必要——
両方省略するとネットワークリスナーの無いREPL専用プロセスとして動く。

## 認証

デフォルトではExecDBはZero-Authで動作する。待受ポート/ソケットへ到達
できる人なら誰でも、認証情報なしに接続できる。`-u NAME`を渡すと、外部
インターフェースに対してのみcleartext-password認証が有効になる(REPL
自体は認証なし——ローカルのプロセスアクセスをすでに必要とするため)。
パスワードは以下の優先順位で決定される。

1. `EXECDB_PASSWORD`環境変数が設定されていれば、それを使う(プロンプト
   なし)。
2. 未設定の場合、REPLモードでは起動時に対話的な`Password:`プロンプト
   (マスク入力)を出す。
3. 未設定の場合、サーバーモード(`-n`)では起動失敗のエラーになる——
   入力を求める相手がいないため。

```sh
EXECDB_PASSWORD=secret execdb -p :5432 -u alice
```

```sh
psql -h 127.0.0.1 -p 5432 -U alice   # パスワード入力を求められる
```

## サーバーモード

`-n`/`--no-repl`は、外部インターフェースのみを提供するバックグラウンド
プロセスとしてExecDBを動かす——REPLも標準入力の読み取りも無い。この
モードでは`.snapshot`コマンドが使えないため、ExecDBは通常の「明示的な
コマンドがあるときだけ保存する」というルールに1つだけ例外を設けている:
`SIGTERM`/`SIGINT`を受け取ると、(`-o`/`-t`に従って)スナップショットを
保存してから終了する。

```sh
execdb -n -p :5432 -o mydb &
kill %1   # 終了前にmydb(または-t指定時はmydb_<timestamp>)へ保存する
```

## タイムスタンプ付きファイル名

`-t`/`--timestamp`を付けると、保存(`.snapshot`、`-o`、サーバーモードの
自動保存)のファイル名に、拡張子の前へ挿入する形で`_YYYYMMDDHHMMSS`という
サフィックスが付く:

| ベースのファイル名 | 結果 |
| :--- | :--- |
| `mydb`(ファイル名省略、ベースは実行中バイナリ名) | `mydb_20260901120000` |
| `mydb_20260101120000`(既にタイムスタンプ付き) | `mydb_20260901120000`(古いものは二重付与せず置き換え) |
| `mydb.exe` | `mydb_20260901120000.exe` |

`-t`を指定しない場合(デフォルト)は、ファイル名をそのまま使う(拡張子
省略時、Windowsでは`.exe`が自動付与される点は変わらない)ため、繰り返し
保存すると同じファイルを上書きし続ける。

## 定期スナップショット

`-i`/`--snapshot-interval`は、タイマーで`.snapshot`相当の保存を繰り返す
——REPLモード・サーバーモードどちらでも有効。長時間セッションでの保存
忘れに対する安全網、あるいはサーバーモードでのシンプルな定期バックアップ
機構として使える。自己上書き(`.overwrite`)には定期実行の対応版は無い
——`.overwrite`自体が「実行中ファイルへの頻繁な書き換え」ではなく
「たまに行う明示的な操作」であるべき、という理由と同じ理由で、別名保存
のみをサポートする。

```sh
execdb -n -p :5432 -i 5m -o mydb   # mydbを5分ごとにスナップショット保存
```
